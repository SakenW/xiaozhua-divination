# 塔罗牌解读

塔罗用于象征性观察和自我反思，不用于替代医疗、法律、财务等专业意见。不要给出宿命论结论。

## 工作流

### 第 1 步：确认问题和牌阵

识别用户输入：

| 参数 | 规则 | 默认 |
| --- | --- | --- |
| 问题/主题 | 用户明确说明；没有也可以做日牌或泛主题 | 泛主题 |
| 牌阵 | 用户指定则使用；否则按场景推荐 | 三张牌 |
| 张数 | 由牌阵决定 | 3 |

牌阵推荐：

| 场景 | 推荐牌阵 |
| --- | --- |
| 日常提醒、今日建议 | 单张牌 |
| 简单问题、快速判断、未指定 | 三张牌 |
| 关系/感情 | 关系牌阵 |
| 复杂局面、深度分析 | 凯尔特十字 |
| 二选一 | Choice：选项 A、选项 B、建议 |

如果用户的问题过于宽泛，先追问他想看感情、事业、财务、人际，还是只做日牌。

### 第 2 步：抽牌

优先使用本地脚本生成牌阵，减少纯 LLM 随机抽牌的不稳定性：

```bash
python3 scripts/run_tarot.py --spread three --question "主题" --seed "可选种子"
```

支持的 `--spread`：`single`、`three`、`relationship`、`celtic`、`choice`。默认输出 JSON；需要人类可读表格时可加 `--format markdown`。当用户没有要求复现时不要传 `--seed`，脚本会使用系统安全随机源；当需要复盘或测试时传入 seed。

按需读取：

- `references/major-arcana.md`
- `references/minor-arcana.md`
- `references/spreads.md`
- `references/interpretation-rules.md`

抽牌规则：

1. 从完整 78 张牌中随机抽取，不重复。
2. 每张牌独立决定正位或逆位，概率各半。
3. 按牌阵位置放置，不为了迎合问题手选“合适”的牌。
4. 若脚本不可用，明确说明无法正式抽牌；可以改为不含具体牌面的反思问题，不能由模型补造抽牌结果。

### 第 3 步：解读

每张牌至少结合三个维度：

1. 牌义：正位/逆位关键词与象征。
2. 位置：该牌在牌阵中代表的领域。
3. 问题：它如何回应用户当前情境。

最后给综合叙事和 2 到 3 条行动建议。

## 输出格式

### 单张牌

```markdown
# 今日塔罗

## {牌名} - {正位/逆位}

{核心牌义，2 到 3 句}

### 提醒
{结合用户主题的解释，2 到 3 句}

### 行动建议
- {具体建议}

---
塔罗提供的是象征层面的观察，最终选择权始终在你手中。
```

### 三张牌

```markdown
# 三张牌阵 - {主题}

## 抽到的牌

| 位置 | 牌 | 方向 |
| --- | --- | --- |
| 过去/背景 | {牌名} | {正位/逆位} |
| 现在/核心 | {牌名} | {正位/逆位} |
| 未来/建议 | {牌名} | {正位/逆位} |

## 分牌解读

### {位置}：{牌名} - {正位/逆位}
{2 到 3 句}

## 综合
{3 到 5 句，把三张牌连成一个清晰判断}

## 行动建议
- {建议 1}
- {建议 2}

---
塔罗提供的是象征层面的观察，最终选择权始终在你手中。
```

## 语气边界

- 用邀请式表达，如“这张牌提醒你留意……”。
- 负面牌要解释为课题、提醒或结构变化，不制造恐惧。
- 死神牌解释为结束、转化、新阶段，不解释为死亡。
- 高塔牌解释为旧结构松动或重建，不解释为灾难必然发生。
- 不说“你注定会……”“必须听牌的指示”“一定失败”。
- 不把关系牌阵解释为缺席者的真实想法、健康、意图或未来行为；第二人称位置只讨论用户可观察到的互动与待澄清的问题。

## 路由边界

用户明确要求占星、八字、紫微、奇门、六爻、九型或 MBTI 时，回到总入口选择对应子技能，不用塔罗硬接所有问题。
